# v0.1.6：刷新失败、核价响应与错误定位

日期：2026-10-17（北京时间）。本轮先复现旧版问题，再补充恢复成功、不同场景隔离、零金额与静态检查的回归。

## 刷新失败后停止自动复用旧结果

同一业务上下文的菜单、商品详情或门店券查询，按最近一次实际有结果的尝试判断。最新尝试失败时，不再跳过它并悄悄使用更早的成功结果：

- 菜单刷新失败，商品选择列表清空。
- 同一商品详情刷新失败，不再自动带入旧套餐、特调默认值。
- 门店券刷新失败，核价重新提示缺少当前场景的有效券校验证据。
- 最新门店查询失败，清空门店与商品选择，避免切换渠道后回退到旧渠道。

只做参数检查、没有发送请求的记录，不会使已有结果失效。另一商品或另一门店、渠道、时段的失败也不会覆盖匹配的详情。重新查询成功后，模板恢复使用最新数据。历史调用保留在报告中，不会被改写成失败。

## 核价响应必须包含有效金额

有响应且没有工具／业务错误时，`calculate-price` 的 `data.price` 必须是有限、非负的数字，单位为分。缺失、字符串、空值、负数等现在产生 `QUOTE_AMOUNT`，不再被当作成功报价。数字0仍然有效。

未填写响应的参数检查不会因此报错；已有业务失败保留原错误，不再追加金额错误。

## 多商品错误分别定位

不完整券参数、套餐选项和特调 key／数量错误，保留各自的 `items[i]`、轮次、子项及特调数组位置。多个商品出现相同问题时不会合并成一个无法定位的提示。跳过异常数组成员后仍使用原始索引。

诊断去重改为集合查找，减少大量不同错误的重复扫描。

## CLI 错误分类

真实 `connect` / `call` 发生传输错误时，仍输出脱敏报告，并以退出码1结束。业务诊断失败、离线失败案例和导入的历史失败报告使用退出码2；文件或执行错误仍为1。JSON-RPC应用错误404不再建议按HTTP会话失效处理。

验证与边界见[验收记录](VERIFICATION.md)。浏览器视觉验收未重复；共享前端纯函数与本机接口通过自动化检查。
